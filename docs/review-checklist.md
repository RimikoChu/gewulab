# 审核清单

审核一个提交请求时照这张清单走。人和 AI 助手都用它。规范见 [`lab-standard.md`](lab-standard.md)，下面括号里是规范的条目编号。

审核的结论只有三种：**可以合并**、**要改**（列出每一条）、**不合并**（说明原因）。最后是否合并由维护者决定。

## 第一步：先跑检查

```bash
npm ci
```

```bash
npm run check
```

不通过就不用往下看了：把输出贴出来，结论是“要改”。

再确认提交者没有为了通过而动检查本身：`scripts/`、`.github/workflows/`、`package.json` 里的脚本、别的实验室的测试，有没有被改。

## 第二步：看改动的范围

- [ ] 说明里写了这是四步中的哪一步（2.1）
- [ ] 勾选了“我已阅读并同意贡献者协议”（没有勾选的不合并）
- [ ] 新实验室的提交只动了：`src/labs/<名字>/`、`labs/<名字>/`、`docs/specs/<名字>.md`、`src/labs.ts` 里它的卡片、`docs/content-structure.md` 里它的那一行、它登记的素材
- [ ] 没有顺手改公共的东西（10.1）。改了的话，要求拆成单独的提交请求
- [ ] 没有新增依赖；有的话说明了理由（7.8）
- [ ] 没有网络请求、外部地址、密钥、和实验无关的脚本（7.7）

## 第三步：对着规格卡看内容

- [ ] 规格卡写明了教材的版本、册、章、节（3.1）
- [ ] 课次和规格卡的总览表一致；每课有一句不超过 20 字的概念、3 到 5 条写成动作的任务（3.2、3.3）
- [ ] **每课抽一个数自己算一遍**，和界面、和 `physics.test.ts`、和规格卡三处一致（3.5、7.3）
- [ ] 界面上的数都能在规格卡里找到来历；“待核实事项”里的内容没有出现在界面上（3.5、3.6）
- [ ] 用词和教材一致；没有科学性错误
- [ ] 简化和示意在规格卡里写明了，容易让学生当真的在界面上标了（3.7）
- [ ] 随堂检测九道题：答案对、讲解对、每课都覆盖到（1.1）

发现编造的数据、引文或教材章节，结论直接是“要改”，并要求提交者把全部内容重新核对一遍。

## 第四步：打开每一课，亲手做一遍

用 `npm run dev` 打开 `/labs/<名字>/index.html`，每一课都做：

- [ ] 照着提示语一步一步做，能做到结论卡弹出来（5.5、5.6）
- [ ] 提示语每一步都说对了下一步；该按的按钮在闪（5.5）
- [ ] 故意做错一次（顺序不对、条件不够）：有提示，不报错、不卡死（5.8）
- [ ] 按“自动演示”，不碰任何东西，这一课能自己走到结论卡（5.11）
- [ ] “重做本课”能回到开头；刷新后进度还在（5.9）
- [ ] 主操作区不超过三个按钮，都是一步到位的；分段选择不超过一组（5.2、5.4）
- [ ] 能拖、能点的东西有提示，也有按钮或键盘的等价入口（5.3、5.11）
- [ ] 动作有过程，不瞬间跳变（5.7）
- [ ] 换课时画面不重建，镜头飞到另一处；来回切几次不出错（4.1）
- [ ] 转动、缩放视角，场景没有穿帮；“复位视角”能回来（4.6）
- [ ] 1366×768 下显示完整；手机竖屏（宽 375）能看、能操作（5.10）
- [ ] 浏览器控制台没有报错

没有条件亲手操作的（比如只能跑无界面浏览器的 agent），用按钮和键盘把每课跑通、每课截图，并在结论里写明“拖动和点击没有人手验证”。

## 第五步：看画面和文字

- [ ] 是一个连续的大场景，各课的地点和画面有区别（4.1、4.4）
- [ ] 器材是那个真实地方会有的东西；主要器材有细节，不只是方块和圆柱（4.2、4.7）
- [ ] 看内部的地方用了剖面（4.5）
- [ ] 界面上没有给开发者看的话，没有多余的图标和装饰（6.1、6.5）
- [ ] 原理默认收起；关键参数有参数格；单位和小数位数统一（6.2、6.3、6.4）
- [ ] 素材都登记了来源和许可；没有照搬别的产品的画面（4.8、3.8）

## 第六步：看代码

- [ ] 计算都在 `physics.ts`，界面和场景文件里没有另算一遍（7.2）
- [ ] 测试核对的是规格卡里的数，不是“函数返回了它自己算的值”这种空测试（7.3）
- [ ] 每个文件开头有说明，注释讲清了为什么（7.9）
- [ ] 没有用 `any`、`@ts-ignore` 之类绕过类型检查（7.10）
- [ ] 没有留下调试代码、没用到的文件

## 第七步：看提交说明是否如实

- [ ] 写了每课怎么验证的、哪些没验证（9.1）
- [ ] 有截图（9.2）
- [ ] 列了和规格卡的出入（9.3）
- [ ] 说明里说“已验证”的，抽两处自己复核一下

说明和实际不符（说跑通了其实没跑通），结论是“不合并”，请提交者重新核对后再交。

## 写结论

```text
结论：可以合并 / 要改 / 不合并

检查：npm run check 通过 / 不通过（贴输出）

要改的地方：
1. [规范 5.2] src/labs/xxx/lesson3.tsx：主操作区有四个按钮。
2. [规范 3.5] 第 4 课界面上的 “1.2×10⁵ Pa” 在规格卡里找不到来历。

我验证了什么：每课用按钮跑到了结论卡；第 2、5 课手算核对了一个数。
我没有验证什么：拖动探头、手机真机。
```

每一条写清楚：哪个文件、什么问题、依据规范第几条。不写“感觉不太好”这种没法照着改的话。
