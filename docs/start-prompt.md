# 让你的 AI 助手参与

把下面这一整段话贴给你的 AI 助手（哪一家的都可以），不用改任何内容。它会自己读仓库、列出还可以认领的实验室让你选，然后开工。

```text
请帮我参与开源项目“格物实验室”：https://github.com/RimikoChu/gewulab

它是一组按课本单元组织的互动三维实验室，每间对应教材的一章。项目有完整的规范，请严格照规范做。

【第一步：读仓库】
把仓库复刻（fork）到我的账号并下载到本地，然后按顺序读：
1. AGENTS.md：写给 AI 助手的提要
2. docs/lab-standard.md：规范正文
3. docs/roadmap.md：总规划表，约 50 间实验室
4. docs/specs/pressure.md 和 src/labs/pressure/：参考实现

【第二步：让我选】
每间实验室有一个议题，认领情况以议题为准。查出还可以认领的：
gh issue list --repo RimikoChu/gewulab --label 可认领 --limit 100
给我列一张表，按学科分组，每间一行（名称、对应教材哪一章、想让学生弄懂什么）。

然后问我一句话：选哪一间？或者我想做一间表里没有的。

- 我选了表里的：在那一间的议题下回复 /认领。看到自动回复“认领成功”才算数；如果回复说已经被别人认领了，告诉我，让我另选。
- 我要做表里没有的：先和我确认学科、学段、教材的章，再开一个“新实验室选题”议题，等维护者贴上“可认领”标签后回复 /认领。等的时间里可以先在本地起草规格卡。

【第三步：直接开干】
认领成功后马上开始写规格卡（docs/specs/<目录名>.md），写完向原仓库提提交请求，说明里写“关联 #议题编号”。之后照规范的顺序往下做：规格卡 → 样板课 → 其余课，每一步一个提交请求，上一步被合并了再做下一步。等合并的时间里，可以先在本地把下一步准备好。

生成骨架用：npm run new-lab -- <目录名> <中文名>
提交前必须通过：npm run check

【最重要的几条，违反会被退回】
- 不编造。数据、教材章节号、引文、历史细节，拿不准的写进规格卡的“待核实事项”并告诉我要核实什么，不要写进界面。
- 计算只写在 physics.ts，每课至少一条测试，数字和规格卡一致。不要为了通过测试去改期望值。
- 一间实验室一个大场景，换课时镜头飞过去。
- 只引用自己的目录、@/lab-kit、@/components/lab/lab-shell；不要改别的实验室。
- 主操作区最多三个一步到位的按钮；提示语永远说明下一步做什么。
- 界面上只有给学生和老师看的话。
- 不联网、不加依赖、不下载素材，除非我同意。
- 不要改规范、检查脚本、lab-kit 来让自己通过。确实需要改，停下来告诉我。

【汇报要如实】
每一课都要把任务从头做到结论卡。告诉我哪些是你实际跑通的，哪些只看了截图，哪些没验证。拖动和点击场景里的物体如果你模拟不了，直接说，我来试。

【发到 GitHub 之前给我看一眼】
议题里的回复和提交请求是以我的名义公开发出去的。发之前把内容给我看，我说“发”再发。其余的事不用问我，直接做。

现在开始第一步。
```

不用 AI 助手也可以参与，见 [`../CONTRIBUTING.md`](../CONTRIBUTING.md)。
